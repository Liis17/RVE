# EngineInput

`engine-input` переводит события геймпадов `gilrs` в снимок четырёх слотов. Крейт не зависит от `engine-script`, окна и renderer: вызывающая сторона передаёт снимок в `ScriptInput::set_pad`.

## Компоненты

- `translate` — чистые функции перевода `gilrs::EventType` в `MapperEvent`. `gilrs` не даёт собрать `Code` и `GamepadId` вне своего крейта, поэтому тесты проверяют эти функции на частях событий, без устройств.
- `GamepadMapper` — таблица слотов. Подключённый пад занимает наименьший свободный слот. Mapper хранит сырое состояние и строит `GamepadSnapshot` с мёртвой зоной стика и порогом триггера.
- `PadGate` — фокусный гейт снимка. Вне принятого ввода пады читаются как подключённые без кнопок и осей. Кнопки, зажатые в момент возврата ввода, маскируются до отпускания. Гейт общий для runtime и редактора.
- `GilrsBackend` — тонкий адаптер. Открывает `Gilrs` без его фильтров по умолчанию, регистрирует уже подключённые пады, опрашивает события без блокировки и держит эффекты force feedback. `discard_events` сбрасывает очередь без применения к маппингу: редактор зовёт его вне Play, чтобы очередь `gilrs` не росла. Runtime держит один бэкенд на scene-потоке; редактор — один на процесс (см. [[Engine/RveEditor]]).

## Контракты

- Слоты: не больше четырёх падов. Пятый игнорируется с warning. Отключение освобождает слот: кнопки отпускаются, оси обнуляются. Повторный `Connected` для занятого id не занимает второй слот. Событие от неизвестного id назначает слот.
- Кнопки: обычные берутся только из press/release, `Changed` для них игнорируется. Аналоговые триггеры — только из значений `*Trigger2`; кнопка триггера срабатывает при значении строго больше `trigger_threshold`. Бамперы — из press/release. D-pad по осям приводится к кнопкам с порогом 0.5.
- Мёртвая зона стика радиальная, с ремапом в [0, 1]; длина вектора после неё не превышает 1. Значения берутся из `[input.gamepad]` проекта (см. [[Engine/EngineProject]]). Единственная мёртвая зона — `stick_deadzone`: gilrs открывается с `with_default_filters(false)`, поэтому его фильтры не применяются.
- Латч коротких нажатий: нажатие кнопки и превышение порога триггера запоминаются в маппере до следующего `snapshot()`. Нажатие, пришедшее и отпущенное между двумя опросами, даёт в одном кадре скриптов `down` и `pressed`, а в следующем — `released`. Удержание не дублирует `pressed`.
- Вибрация: `GilrsBackend::rumble` получает уже нормализованные значения (нормализация — в `engine-script`, `RumbleRequest`). Эффект ограничен длительностью через `Repeat::For`: gilrs иначе повторяет его бесконечно. Пад без force feedback пропускается с debug. Новый запрос на том же слоте заменяет предыдущий, потому что дроп эффекта его останавливает. `stop_rumble` останавливает все.
- Доставка за кадр: `rumble_frame` оставляет для каждого слота только последний запрос кадра; `pad = 0` покрывает все слоты, нулевой запрос тоже сохраняется и останавливает предыдущий эффект. Лимит 256 запросов за кадр и отказ скрипту — в [[Engine/EngineScript]].

## Потоки и ограничения

- `gilrs` 0.11.2 содержит `assert_send::<Gilrs>()` для не-wasm целей. Бэкенд всё равно создаётся и опрашивается на потоке владельца: scene-поток runtime и главный поток редактора.
- Windows: бэкенд WGI отдаёт события только активному окну. Ввод и так принимается только при фокусе.
- macOS: бэкенд IOKit работает в собственном потоке с CFRunLoop. Runtime на macOS и реальные пады не проверены, нет оборудования.
- macOS: вибрации нет. `gilrs-core` 0.6.8 возвращает `is_ff_supported() == false` для IOKit, поэтому rumble пропускается с debug-логом. Проверено по исходнику крейта, не на железе.
- Снимок передаётся уровнями, а не очередью событий. Короткие нажатия не теряются благодаря латчу.
- Направление D-pad по Y (вверх — положительное) принято по соглашению `LeftStickY`. На железе не проверено.

## Ручная проверка на железе

Автотесты не открывают устройства. Перед релизом проверить на Windows с падом XInput/WGI и на macOS (там только ввод, без вибрации):

- вибрация заканчивается через `seconds`, а не продолжается после окончания запроса;
- одно нажатие кнопки даёт одно `pressed` и не дублируется при удержании и отпускании;
- Stop в редакторе отпускает пады и останавливает вибрацию; следующая сессия Play стартует без залипших кнопок.
