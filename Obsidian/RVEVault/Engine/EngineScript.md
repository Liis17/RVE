# EngineScript

Parent: [[Index]]

## Назначение и границы

`engine-script` связывает `engine-scene::World` с lite-скриптами Lua 5.4 и heavy-скриптами Rust, зарегистрированными игрой. Крейт не зависит от runtime, renderer, window или платформенных адаптеров. `ScriptHost` и один принадлежащий ему `mlua::Lua` создаются на потоке скриптов; `engine-script` собирается без feature `send`, поэтому host остаётся `!Send`.

## Контракт

- `ScriptTime` передаёт elapsed и frame; `ScriptTransform` содержит локальные position, rotation в градусах и scale. Каждая фаза получает свежую копию локальной трансформации объекта. Изменения записываются в `World` только после успешного callback и проверки конечности всех координат.
- `ScriptParams` — `BTreeMap<String, engine_scene::ParamValue>`; `ParamValue` также переэкспортирован из `engine-script`. В Lua значения соответствуют boolean, integer, number, string и таблицам-массивам с индексом от 1. Heavy factory получает те же параметры по ссылке.
- Хост обходит объекты `World` по порядку. Для каждого объекта он компилирует незагруженные lite-файлы по мере встречи, создаёт lite-экземпляры в порядке объявления, затем вызывает heavy-фабрики в порядке объявления и переходит к следующему объекту. Таким образом, загрузка lite-файлов и heavy-фабрик чередуется по объектам.
- `start` выполняется один раз до первого `update` (при необходимости `update` вызывает его сам). `destroy` выполняется один раз для запущенных и включённых экземпляров.
- Lite-файл — Lua chunk с именем канонического virtual path, возвращающий таблицу-класс. Необязательные `on_start`, `on_update(self, dt)` и `on_destroy` должны быть функциями. Экземпляр хранит `params`, `object.id/name` и `transform`; для сохранения изменений векторное свойство присваивается таблицей `{x, y, z}`.
- Каждый lite-файл компилируется один раз в собственном `_ENV`; все экземпляры этого файла используют его класс и окружение. Таблица `rve` и вложенная таблица `rve.time` общие для всех файлов и изменяемы скриптами. Хост сохраняет ссылку на `rve.time` и в начале каждой фазы обновляет `elapsed` и `frame` через raw-запись, не вызывая Lua-метаметоды. `rve.log(...)` и `print(...)` используют захваченную функцию Lua `tostring`, соединяют аргументы пробелом и добавляют `Info` в очередь событий. Строки с неверным UTF-8 записываются с заменой некорректных последовательностей на `�`.
- `frame` передаётся как Lua integer до `i64::MAX`; большее значение передаётся как float, поэтому возможна потеря точности.
- `HeavyScript: Send` задаёт lifecycle Rust-скрипта. Игровой крейт регистрирует фабрики через `HeavyRegistry::register`. Имя должно быть ASCII `[A-Za-z0-9_]{1,64}`. Неверное имя и повторная регистрация возвращают `HeavyRegistrationError`, а не панику.

## Lua sandbox и ошибки

Зависимость `mlua` закреплена как `=0.12.2` с features `lua54` и `vendored`; системный Lua не нужен. Lua base library открыта библиотекой mlua; дополнительно загружаются только table, string, math и utf8. `coroutine`, `io`, `os`, `package`, `debug`, `dofile`, `loadfile` и `require` недоступны. `load` принимает только текстовые чанки с режимом `t`; без явного окружения загруженный chunk использует `_ENV` своего файла. Бинарный bytecode отклоняется.

Окружения файлов наследуют общую базовую таблицу функций и значений (`string`, `table`, `math`, `utf8`, `rve`, `print` и другие). Присваивание глобала вроде `rve = nil`, `tostring = nil` или `foo = 1` остаётся в `_ENV` этого файла. Таблицы стандартных библиотек общие: например, изменение `string.upper` видно из всех файлов. Это ограничение версии 1.

Память одного Lua state ограничена 256 MiB через `Lua::set_memory_limit`. Ошибка Lua при превышении лимита отключает вызвавший её экземпляр; при top-level chunk во время загрузки она становится `ScriptLoadError`. `collectgarbage` разрешает только `collect`, `count` и `step`; вызов без аргументов эквивалентен `collect`, остальные режимы дают Lua runtime error.

Runtime error Lua, panic heavy-скрипта или не конечная трансформация отключают только соответствующий экземпляр. Трансформация, изменённая этим неуспешным вызовом, не попадает в `World`; отключённый экземпляр больше не вызывается, в том числе для `on_destroy`. Ошибки загрузки включают virtual path либо id объекта и имя heavy script. Runtime-ошибки и логи буферизуются в `ScriptEvent` с уровнем, source (`scene/object/script`) и сообщением; вызывающий получает их через `drain_events()`.

`ScriptInterruptHandle::new()` создаёт сигнал, который можно передать в `ScriptHost::load_with_interrupt` до запуска host. `load` создаёт собственный handle; `interrupt_handle()` возвращает его clone. В обычной работе Lua hook вызывается раз в 1000 инструкций и проверяет атомарный флаг. После обнаружения interrupt hook переключается на каждую инструкцию и повторно бросает ошибку, поэтому Lua `pcall`/`xpcall` не могут перехватить отмену и продолжить цикл. Hook действует также во время исполнения top-level chunk при загрузке. Heavy-фабрики и heavy callbacks — синхронный Rust-код, их прервать нельзя.

Если флаг установлен в начале фазы либо перед вызовом lite, lite-экземпляры пропускаются и отключаются; после interrupt `on_destroy` им не вызывается. Host добавляет одно событие `scripts interrupted` на весь host, если в нём есть хотя бы один lite-экземпляр, без событий по одному на экземпляр. Heavy-экземпляры продолжают выполнять свои фазы.
