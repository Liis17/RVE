# RveSdk

Parent: [[Index]]

## Назначение

`rve-sdk` — самостоятельный крейт без зависимостей, который задаёт C ABI и гостевой Rust API для игровых скриптов, собираемых в `cdylib`. Он не зависит от движка и включает `Script`, `Context`, `Transform`, а также owned-типы значений и параметров. Host-side загрузка и вызовы описаны в [[Engine/EngineScript]].

Игровой crate подключает SDK как зависимость и объявляет cdylib-target:

```toml
[lib]
crate-type = ["cdylib"]

[dependencies]
rve-sdk = { path = "<sdk>/rve-sdk" }
```

Каталог `<sdk>` создаётся командой `rve-build sdk --output <dir>` из checkout и
содержит standalone crate `rve-sdk/` без `target/`. Для разработки из checkout можно
указывать `../../engine/rve-sdk`; собранный SDK подключается тем же path-зависимым
способом без исходников движка. При распространении пары бинарников `rve-build` и
`rve-player` сохраняйте рядом `rve-sdk.toml`: он включает SDK-режим и фиксирует ABI
и платформу.

`rve-build scripts` синхронизирует гостевой crate в `<project>/.rve/sdk/rve-sdk`
перед сборкой, независимо от того, запущен ли builder из checkout или переносимого
SDK. Новый проект использует этот путь из `Scripts/Cargo.toml`:

```toml
[dependencies]
rve-sdk = { path = "../.rve/sdk/rve-sdk" }
```

Папка `.rve/` находится вне `Assets/` и исключена шаблонным `.gitignore`.
Синхронизация обновляет изменённые файлы, сохраняет mtime совпадающих и удаляет
исходники API, которые исчезли из установленной версии.

SDK marker рядом с переносимым `rve-build` фиксирует точный ABI. Marker ABI v16
несовместим с builder/player ABI v17: пересоздай переносимый комплект командой
`rve-build sdk`. Для проектов builder синхронизирует текущий SDK в `.rve/sdk`
перед сборкой Rust scripts.

Реализация создаёт тип, реализующий `rve_sdk::Script`, и функцию-фабрику,
принимающую `&rve_sdk::Params`. `rve_sdk::export_scripts!` экспортирует ABI entry
point с именами heavy-скриптов, на которые ссылаются сцены. Пример —
`examples/demo-game/HeavyScripts`; `rve-build` проверяет cdylib и имена скриптов при
сборке проекта ([[Engine/RveBuild]]).

Скрипт может объявить типизированные параметры необязательным блоком после фабрики:

```rust
rve_sdk::export_scripts! {
    "Bobber" => create_bobber {
        amplitude: f32 = 0.15,
        speed: f32 = 1.4 (0.0..=10.0) "Speed",
    }
}
```

- Типы: `bool`, `i64`, `f32`/`f64` (float), `&str`, `[f32; 3]` (vec3), `Option<Object>`, `Asset`, `component(rigid_body)`, `enum("idle", "run")`, `Color` и `Vec<T>`. Для enum первым значением списка задаётся default; `Vec<T>` имеет пустой default.
- Object/component по умолчанию равен `None`; asset задаёт путь строковым литералом. Для vec3 и `Color` используются три литерала, для enum default — один из объявленных вариантов, для `Vec<T>` поддерживается типизированный массив.
- Диапазон `(min..=max)` допустим только у числовых типов. Label — необязательный литерал в конце.
- Таблицы строятся в const-контексте как `'static`.
- Host проверяет значения и заполняет default до вызова фабрики, поэтому `Params` приходит заполненным ([[Engine/EngineScript]]).
- Форма без блока остаётся рабочей: такой скрипт схемы не объявляет и получает `params` сцены без проверок.

Синтаксис отличается от «естественного» Rust из-за ограничений `macro_rules`: после фрагмента `expr` нельзя ставить `(`, поэтому default — литерал.

## Контракт ABI

- Текущая версия — `RVE_SCRIPT_ABI_VERSION = 17`, минимальная принимаемая — `RVE_SCRIPT_ABI_MIN_VERSION = 3`. ABI v8 дописывает после audio callbacks nullable `cursor_state`, `set_cursor_visible` и `set_cursor_locked`, сохраняя прежние префиксы, поэтому guest ABI v7 не читает этот хвост. ABI v9 дописывает в конец `RveHost` (после cursor-хвоста) nullable callbacks `spawn`, `destroy`, `object_state`, `prefab_load`, `prefab_unload` и `prefab_state` и `RveSpawnOptions` (`repr(C)`, 96 байт): поле `flags` с битами `RVE_SPAWN_HAS_*`, затем `position`, `rotation_deg`, `scale`, `velocity`, `parent` (handle), `name` и `id` (`RveStr`). Неизвестный бит `flags` даёт отказ. Коды состояния объекта — `RVE_OBJECT_DEAD`, `PENDING`, `ALIVE` (0, 1, 2); коды префаба — `RVE_PREFAB_UNKNOWN` (0), `RESIDENT`, `UNLOADED`, `LOADING`, `LOADED`, `UNLOADING`, `FAILED` (1–6). Версия 9, а не 8, выбрана потому, что v8 уже закреплён cursor-хвостом, и хост v8 принял бы модуль, который читает spawn-поля. ABI v10 дописывает в конец `RveHost` (после spawn-хвоста) nullable callbacks `animation_*` для аниматора объекта: `animation_play`, `animation_set_weight`, `animation_set_parameter`, `animation_set_speed` и `animation_stop`. Параметры `play` передаются в `RvePlayAnimationParams`: `fade`, `looping` (−1 — значение компонента, 0 или 1) и `then` (`RveStr`, пустая строка — нет перехода). Методы гостевого API возвращают `AnimationError { Unavailable, Rejected, InvalidInput }`; хост без callbacks v10 даёт `Unavailable`. Версия 10, а не 9, выбрана потому, что v9 уже закреплён spawn-хвостом, и хост v9 принял бы модуль, который читает animation-поля. ABI v7 дописывает в конец `RveHost` nullable audio callbacks `audio_play_source`, `audio_stop_source`, `audio_set_source_volume`, `audio_play_clip`, `audio_stop_voice` и `audio_set_group_volume`, а также `RveAudioParams` (`group`, `volume`, `looping`, `has_position`, `position`). Callbacks возвращают `RveStatus` как `u32`: `0` — успех, `1` — отказ; причина сразу попадает в события скрипта как Error, даже если гость проигнорировал статус. Идентификаторы голосов — `u64`, ненулевые. ABI v3 добавил `params`/`param_count`, ABI v4 — nullable `command` в конец дескриптора, ABI v6 — nullable `collision` в конец `RveScriptDesc`. Host сохраняет отдельные `RveScriptDescV3` и `RveScriptDescV4` layouts и нормализует их без чтения недостающего хвоста: у v3 нет command и collision callback, у v4 и v5 — command без collision. В конец `RveHost` ABI v4 добавлены nullable `register_command`/`unregister_command`; ABI v5 дописывает nullable action-input callbacks `action_state`, `action_value`, `input_context`, `set_input_context`, `rebind_action`, `action_binding` и `reset_bindings`; ABI v6 дописывает nullable physics callbacks для raycast, dynamic body commands, character movement/grounding и collider enable state, сохраняя прежние префиксы. `action_state` использует флаги `RVE_INPUT_DOWN/PRESSED/RELEASED` и принимает только button actions; `action_value` читает axis/vector2 по `RVE_ACTION_*`, помещая значение axis в `x`. Для пустого корректного binding slot `action_binding` успешно возвращает пустую строку на index 0; неверный контекст/действие/слот возвращает `false`. Guest-код ABI3/4/5 сохраняет совместимость через свой префикс `RveHost` и не читает хвост v6. ABI v1/v2 не принимаются. ABI v2 ранее добавлял camera callbacks в конец `RveHost`, сохранив v1-префикс. Любое несовместимое изменение layout требует повышения версии. `RveModule` начинается с `RveHeader` с версией и размером заголовка; host сначала читает и проверяет его и только затем интерпретирует таблицу соответствующей версии.
- ABI v11 дописывает в конец `RveHost` (после animation-хвоста) nullable `gamepad_state` и `gamepad_rumble`. `RveGamepadState` (`repr(C)`, 40 байт) несёт подключение, биты кнопок текущих, нажатых и отпущенных и шесть осей. Модули ABI v3–v10 продолжают загружаться.
- ABI v12 дописывает в конец `RveHost` (после gamepad-хвоста) nullable callbacks `get_post_process` и `set_post_process` для камер и `RvePostProcessSettings` (`repr(C)`, плоские поля, коды `RVE_EXPOSURE_MODE_*` и `RVE_AO_QUALITY_*`). Layout `RveCameraSettings` не меняется; его exposure и tonemapper проксируют к постобработке камеры и помечены устаревшими. Версия 12, а не 11, выбрана потому, что v11 уже закреплён gamepad-хвостом. Guest-обёртки — `Object::post_process(ctx)` и `Object::set_post_process(ctx, …)`. Модули ABI v3–v11 продолжают загружаться.
- ABI v13 дописывает в конец `RveHost` (после post-process хвоста) nullable net callbacks (режим, локальный участник, участники, отправка сообщения и методы объекта: id, владелец, владение, authority, назначение владельца и отправка) и добавляет в конец `RveScriptDesc` nullable callback `net_event` после collision-хвоста v6. Модули версий 6–12 читаются как `RveScriptDescV6` без net-полей, версия 13 — как `RveScriptDescV13`; `RVE_SCRIPT_ABI_MIN_VERSION` не менялся. Host без net callbacks (`None`) отвечает гостю `NetError::Unavailable`. Модуль v13 на host v12 отклоняется по версии. Переносимый SDK после смены ABI пересоздаётся командой `rve-build sdk` ([[Engine/RveBuild]]). Версия 13, а не 12, выбрана потому, что v12 уже закреплён post-process хвостом.
- ABI v14 дописывает в конец `RveHost` (после net-хвоста) nullable callbacks `screen_shader_count`, `get_screen_shader` и `set_screen_shader` и структуру `RveScreenShaderState` (`repr(C)`, 68 байт: `enabled` и `params[16]`). Слоты нумеруются с нуля; путь и стадия экранного шейдера задаются сценой и callbacks их не меняют. Префикс `RveHost` прежний, поэтому модули v3–v13 загружаются без изменений. Версия 14, а не 13, выбрана потому, что v13 закреплён net-хвостом. Гостевые методы камеры описаны в [[Engine/EngineScreenShaders]].
- ABI v15 сохраняет весь `RveHost` v14 без новых callbacks. `RveValue` получает теги object handle и asset string; новый `RveParamDesc` добавляет nullable-by-empty `argument` в конец для component, asset extension, enum values и recursive array element kind. ABI v3–v14 используют прежний `RveParamDescV13`; модули ABI v3–v14 продолжают загружаться, минимальная версия остаётся 3. `Option<Object>` и component refs передаются фабрике как handles, заранее заполненные host-ом.\n- Таблица модулей и описания скриптов рассчитаны на статическое время жизни. Макрос `script_module!` строит статическую таблицу; `export_scripts!` экспортирует функцию `rve_script_module`, возвращающую указатель на модуль.
- ABI v16 дописывает в конец `RveHost` (после screen shader хвоста v14) nullable callbacks иерархии и активности: `object_set_active`, `object_is_active`, `object_active_in_hierarchy`, `object_parent`, `object_set_parent`, `object_children`, мировые позиция и поворот (`object_world_position`/`object_set_world_position`, `object_world_rotation`/`object_set_world_rotation`), `object_tag`/`object_set_tag`, `object_layer`/`object_set_layer`, `object_has_component`, `find_objects_by_name`, `find_objects_by_tag`, `script_set_enabled` и `script_enabled`. Списки пишутся в пару вызовов «число и буфер» (как `net_peers`). Компоненты проверяются по именам `RVE_COMPONENT_NAMES`. В конец `RveScriptDesc` добавлены nullable `on_enable` и `on_disable` (`RveStartFn`). Дескриптор v14 сохранён как `RveScriptDescV15`; модуль v14 читается с `on_enable = on_disable = None`. Переносимый SDK после смены ABI пересоздаётся командой `rve-build sdk`.
- ABI v17 дописывает в конец `RveHost` (после v16) nullable callbacks физики: `physics_get_collider`/`physics_set_collider`, `physics_get_rigid_body`/`physics_set_rigid_body`, `physics_get_controller`/`physics_set_controller` (значения `RveColliderValue`, `RveRigidBodyValue`, `RveControllerValue`), `physics_simple_move`, `physics_jump`, `physics_vertical_velocity`, `physics_overlaps` (список в пару вызовов), `physics_overlap`, `physics_raycast_all` и `physics_shape_cast` (формы `RveQueryShape`, опции `RveQueryOptions`: `layer_mask`, `include_triggers`, список `ignore`). Вид события `RVE_TRIGGER_STAY` (4) вызывает `on_trigger_stay`. Дескриптор скрипта не менялся, модули v15 читаются тем же путём.
- `RveHost` и его opaque context передаются на время одного guest callback и действуют только в нём и на вызывающем потоке. Сохранять их указатели после вызова нельзя.
- ABI-строки, значения и параметры передаются как заимствованные данные. SDK копирует входные значения и параметры в owned `Value` и `Params`; память, выделенную одной стороной, освобождает только её владелец, вторая сторона не должна освобождать чужую память.
- Handle объекта кодирует `(generation << 32) | (index + 1)`; ноль означает отсутствие объекта. Освобождение слота увеличивает поколение, поэтому устаревший handle не оживает на переиспользованном слоте. Объекты документа имеют поколение 0, поэтому прежнее кодирование совместимо со всеми поддерживаемыми версиями ABI v3–v9. Pending-handle из `spawn` принимают `destroy`, `object_state` и `send` по его id; `find` и чтение трансформации ждут, пока объект появится в мире.
- `RveHost` предоставляет `find_object`, `object_id`, `object_name`, `get_local`, `set_local`, `world_matrix`, `send` и `broadcast`, а также `log` и callbacks ввода. `Key` и `MouseButton` имеют явные стабильные коды; key/button state — битовая комбинация `DOWN = 1`, `PRESSED = 2`, `RELEASED = 4`. Неизвестный код возвращает ноль. `cursor_position`, `mouse_delta` и `wheel_delta` копируют `[f32; 2]` через выходной указатель и возвращают `bool`. ABI v2 дописывает nullable callbacks `get_camera_settings`, `set_camera_settings`, `active_camera` и `set_active_camera`; ABI v5 дописывает nullable callbacks физики. Отсутствующие optional callbacks представлены SDK как `PhysicsError::Unavailable`, неудачный вызов — `Rejected`, а конечность и диапазоны входа проверяются до вызова. `RveCameraSettings` — `repr(C)` из 40 байт: `fov_deg`, `near`, `far`, `render_scale`, `clear_color`, `exposure_ev`, `anti_aliasing` и `tonemapper`; последние два поля — `u32` с фиксированными кодами. Чтение в `create` разрешено; начальный снимок может быть нулевым. Host-функции работают с любым валидным объектом текущего мира. `world_matrix` копирует 16 `f32` в column-major порядке. Возвращаемые строки и все указатели действительны только до завершения callback.
- `send` адресует объект по scene id до 256 UTF-8 байт, `broadcast` адресует все включённые экземпляры. Оба callback принимают borrowed `RveValue`; ABI host проверяет и копирует его в `ParamValue` до возврата. Неизвестная или слишком длинная цель, а также значение, отклонённое ограничениями сообщений, возвращают `false`. Во время `create` host запрещает записи и отправку сообщений, но разрешает чтение и логирование. Ограничения сообщений описаны в [[Engine/EngineScript]].
- Каждый lifecycle callback, включая каждую доставку `message` и physics event, транзакционный. Локальные записи, camera settings, выбор активной камеры, состояние курсора, сообщения, body-команды, grounded state и collider enable state применяются только после успешного завершения callback; настройки камеры дополнительно проверяются по диапазонам. При `Error`, `Panicked`, poisoned host callback, не конечной трансформации или неверных настройках изменения отбрасываются. Логи не откатываются.
- Callback возвращает `RveStatus`: `Ok` при успехе, `Error` при ошибке и `Panicked` при пойманной панике. Текст ошибки передаётся host через `set_error`.
- Обе стороны ABI не допускают unwind через C boundary: SDK-обёртки ловят Rust panic и возвращают статус, host ловит панику внутри host callback и отклоняет весь вызов. Сборка guest-кода с `panic = "abort"` завершает процесс при панике; перехватить её нельзя.

## Гостевой API Rust

Гостевой API v16: `Script::on_enable` и `Script::on_disable` (с пустыми реализациями по умолчанию); у `Object` — `parent`, `children`, `set_parent(ctx, parent, keep_world)`, `is_active`, `active_in_hierarchy`, `set_active`, `world_position`/`set_world_position`, `world_rotation`/`set_world_rotation` (градусы Эйлера YXZ), `tag`/`set_tag`, `layer`/`set_layer`, `has_component`, `components`; у `Context` — `find_by_name`, `find_all_by_name`, `find_with_tag`, `find_all_with_tag`, `set_enabled(bool)` и `enabled()` для текущего экземпляра. Записи коммитятся вместе с callback, как у остальных методов.

Гостевой API v17: `Script::on_trigger_stay`; у `Object` — `collider`/`get_collider`/`set_collider`, `rigid_body`/`get_rigid_body`/`set_rigid_body`, `controller`/`get_controller`/`set_controller`, `simple_move`, `jump`, `vertical_velocity`, `overlaps`/`get_overlaps`, `is_grounded` и `set_collider_enabled`; у `Physics` — универсальные `overlap`/`shape_cast` и именованные `overlap_sphere`/`overlap_box`/`overlap_capsule`, `sphere_cast`/`box_cast`/`capsule_cast`, а также `raycast_all`. Типы `Collider`, `RigidBody`, `CharacterController`, `QueryShape` и `QueryOptions` задают значения компонентов и фильтры `layer_mask`, `include_triggers`, `ignore`; именованные методы используют те же ABI callbacks, что и универсальные. Записи коммитятся вместе с callback, как у остальных методов. Модули v3–v15 продолжают загружаться на v16 host.

`Value::Object(Object)` и `Value::Asset(String)` доступны в сообщениях; объектная ссылка кодируется handle-ом, path — строкой. `Params` также выдаёт эти типы и optional `Object`, а фабрика получает object/component handles уже заполненными host-ом до создания `Context`.

`Script` поддерживает `on_start`, `on_update`, `on_message`, `on_collision_enter`, `on_collision_exit`, `on_trigger_enter`, `on_trigger_exit`, `on_trigger_stay` и `on_destroy`. `on_trigger_stay` вызывается раз за кадр update для каждой активной trigger-пары, а не на каждый подшаг физики. `on_message(&mut self, ctx, sender, name, value)` вызывается для каждой доставки; `Value` уже скопирован в owned память гостя. Physics events идут единым nullable ABI v5 callback с kind, other handle, point и normal; SDK dispatch вызывает соответствующий trait method, default implementation ничего не делает. Сетевые события идут через ABI v13 `net_event`: трейт получает `on_net_message`, `on_peer_connected` и `on_peer_disconnected` с пустыми реализациями по умолчанию.

Сетевой API гостя: `Context::net()` возвращает `Net` для режима (`mode`, `is_server`, `is_client`), номеров (`local_peer`, `peers`) и отправки `send` с адресатом `Server`, `All` или `Peer`. У `Object` есть `net_id`, `net_owner`, `is_owner`, `has_authority`, `set_net_owner` и `net_send`. Ошибки — `NetError`: `Unavailable` (host без net callbacks), `Rejected` (host отказал в текущей фазе или состоянии) и `InvalidInput` (нарушены лимиты сообщения или адресат недопустим). Сетевые вызовы транзакционны, их семантика и лимиты описаны в [[Engine/EngineScript]]. `Context::find(id)` возвращает `Option<Object>`; `Object` — `Copy` handle без указателя на host, стабильный в пределах загруженной сцены и пригодный для хранения в состоянии скрипта. Каждая операция с handle требует `Context` текущего callback. `Context::object()` возвращает handle объекта, которому принадлежит текущий экземпляр.

Через `Object` можно прочитать или записать локальную трансформацию, получить column-major world matrix, id и name. `Object::camera_settings(ctx)` возвращает `Option<CameraSettings>`; `set_camera_settings(ctx, settings)` и `activate_camera(ctx)` возвращают `false`, если callback недоступен, объект не камера или запись запрещена. `CameraSettings` содержит `fov_deg`, `near`, `far`, `render_scale`, линейный `clear_color`, `exposure_ev`, `anti_aliasing` и `tonemapper`; enum коды доступны через `from_code` и `code`. `Context::active_camera()` возвращает `Option<Object>`. Отсутствующий camera callback означает API недоступен и аккуратно отображается в `None`/`false`. `Context::send(target_id, name, &Value)` и `Context::broadcast(name, &Value)` возвращают `bool`; `false` означает неизвестную либо превышающую 256 UTF-8 байт цель для `send`, недоступную фазу записи или отказ host из-за ограничений сообщения. `Context::log_info`, `log_warn` и `log_error` создают соответствующий уровень события. `Context.transform` остаётся удобным полем собственной трансформации.

`Context::physics().raycast` выполняет read-only запрос и по умолчанию исключает triggers; host также исключает капсулу controller текущего скрипта. `raycast_with_options` задаёт `include_triggers` и optional ignored object. `Object` предоставляет dynamic-only `get_velocity`, `set_velocity`, `add_impulse` и `add_force`; controller-only `move_character` и `is_grounded`; а также `set_collider_enabled`/`is_collider_enabled`. Методы возвращают `PhysicsError::{Unavailable, Rejected, InvalidInput}` для отсутствующего optional callback, отказа host и некорректного вектора или результата.

`Context::input()` возвращает read-only `Input`: `key_down/pressed/released(Key)`, `mouse_down/pressed/released(MouseButton)`, `cursor()`, `mouse_delta()` и `wheel()` остаются сырым API. `Input::action_down`, `action_pressed` и `action_released` возвращают button edges; `Input::axis` и `Input::vector` возвращают `Option`, `Input::context()` — активный контекст как `Option<String>`, а `Input::bindings(context, action, slot)` различает неверный слот (`None`) и пустой (`Some(Vec::new())`). `Input::pressed_inputs()` перечисляет raw physical inputs с pressed edge. Запись выполняется через `Context::set_input_context`, `Context::rebind(context, action, slot, &[PhysicalInput])` и `Context::reset_bindings`; bool `false` означает отсутствующий callback или отклонённую запись. `PhysicalInput` представляет `Key` или `MouseButton` и умеет разбирать/форматировать `Mouse.<Button>`, а также `Gamepad.<Button>` и `Gamepad<N>.<Button>`. Геймпады доступны через `Input::gamepad(pad)`: слот 1–4 или агрегат при `pad = 0`, с подключением, кнопками, осями и стиками. Нет callback и неверный слот дают отключённое состояние. `Input::rumble(pad, strong, weak, seconds)` возвращает `false`, если host отклонил запрос. Стабильные коды кнопок и осей описаны в `engine/rve-sdk/src/abi.rs`.

Spawn API: `Context::spawn(path, &SpawnOptions)` возвращает `Option<Object>` — pending-объект, который появится в мире в конце текущей фазы. `SpawnOptions` строится builder-методами `position`, `rotation_deg`, `scale`, `velocity`, `parent`, `name` и `id`; неконечное значение даёт `None` до вызова host. `Object::destroy(ctx, delay)` возвращает `bool`, `Object::is_alive` и `Object::is_pending` читают состояние. `Context::prefabs()` даёт `load` и `unload` (`bool`) и `state(path) -> PrefabState`. Путь префаба принимается со слешем или без (`/prefabs/x.rveprefab` и `prefabs/x.rveprefab`): host нормализует его одинаково. Старый host без callbacks даёт `None`, `false` или `PrefabState::Unavailable`. Отказ host (`0` или `false`) пишет Error-событие с причиной. В `create` spawn, destroy и загрузка префабов запрещены.
Курсор окна: `Context::set_cursor_visible(bool)` и `Context::set_cursor_locked(bool)` ставят запись в транзакцию callback и возвращают `false`, если callback недоступен, запись запрещена (`create`) или отклонена. `Input::cursor_visible()` и `Input::cursor_locked()` возвращают состояние с учётом записей этого callback, а `None` означает host без ABI v8. Применение и откат следуют общим правилам транзакции из [[Engine/EngineScript]].

Cursor — физические пиксели окна; до первого `CursorMoved` позиция равна `[0, 0]`. `CursorLeft` не обрабатывается, поэтому позиция сохраняется после выхода курсора из окна, потери фокуса и перехода в Background. Mouse delta — относительное движение устройства из `DeviceEvent::MouseMotion`, wheel — накопление в строках. На Windows для движения используется raw input; на macOS дельта может включать системное ускорение, это не проверено. На macOS при зажатом `Cmd` система может не прислать key-up других клавиш, и такая клавиша останется down до потери фокуса; это известное ограничение платформы, не проверенное в проекте. `Key` и `MouseButton` совпадают по именам с `engine-window` и Lua API. Снимок одинаков для всех экземпляров одного update; `create` видит пустой сырой snapshot, `start` — последний установленный snapshot или пустой, если update ещё не было. Перед `destroy` host очищает pressed/released и дельты, сохраняя down и позицию курсора последнего snapshot.

`Context::console` действует только в рамках текущего callback. `write(text, ConsoleLevel::{Log, Warning, Error})` отправляет сообщение соответствующего уровня. `register(name, Option<&str>)` и `unregister(name)` управляют принадлежащими экземпляру командами; для обработки реализуется `Script::on_command(ctx, name, args)`. Команды используют ABI v4 callbacks, а вызов гостевого обработчика транзакционный; детали регистрации и срока жизни описаны в [[Engine/EngineConsole]].

Если callback меняет и `Context.transform`, и собственную трансформацию через `Object::set_transform`, конечное изменившееся поле `Context.transform` перекрывает запись handle. Если поле осталось равным начальному значению, применяется запись через handle. Матрица мира остаётся снимком фазы: локальная запись не пересчитывает её внутри вызова или до следующей фазы. Полный lifecycle и расписание сообщений описаны в [[Engine/EngineScript]].

Звуковой API гостя: `Object::play_sound`, `stop_sound`, `set_sound_volume` и `Context::play_clip(path, ClipOptions)`, `stop_voice`, `set_group_volume`. `play_clip` возвращает id голоса. Ошибки — `AudioError`: `Unavailable` для хоста без audio callbacks (ABI до v7), `Rejected` при отказе хоста, `InvalidInput` для неконечных значений и громкости вне `0..=4` (`MAX_AUDIO_VOLUME`, совпадает с `engine_scene::MAX_AUDIO_VOLUME`). Клип объявляется в `[[assets]]` сцены, см. [[Engine/EngineAudio]].
