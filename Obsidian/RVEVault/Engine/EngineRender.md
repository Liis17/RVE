# EngineRender

Parent: [[Index]]

## Назначение

`engine-render` создаёт Vulkan instance, surface, устройство и swapchain, запекает HDR panorama или procedural sky в image-based lighting (IBL), вычисляет GPU-кластеры локальных источников, записывает directional и point/spot shadow maps и рисует PBR metallic-roughness меши с tangent-space normal maps, emissive, ambient occlusion и PCF-тенями в HDR offscreen-target. Поток сцены: clustered compute → directional shadows → local shadows → opaque/mask → skybox → transparent blend → tonemap → output. Крейту не нужна конкретная оконная библиотека: окно передаёт display/window handles через `raw-window-handle`.

## Зависимости и взаимодействия

- Использует ash 0.38.0 и raw-window-handle 0.6.2; naga 30.0.1 — только build-зависимость. naga 30.0.1 не собирает `glsl-in` без `wgsl-in` или `spv-in`, поэтому в `Cargo.toml` дополнительно включена `wgsl-in`. [[Engine/EnginePlatform]] предоставляет загрузку Vulkan, требования платформы и surface через ash-window 0.13.0.
- Используется в [[Engine/Sandbox]] и [[Engine/RveEditor]], которые передают `Arc<Window>` из [[Engine/EngineWindow]]. Renderer получает UI-треугольники без зависимости от egui; редактор переводит egui output и управляет scene viewport-ами.
- `engine-render` намеренно не зависит от winit; это проверяется командой `cargo tree -p engine-render`.

## Ограничения и важные детали

- Требуется Vulkan API не ниже 1.3, `dynamicRendering`, `synchronization2`, `VK_KHR_swapchain`, graphics+present queue family и FIFO surface. Общая graphics queue должна также поддерживать compute. `shaderStorageImageExtendedFormats` и `R16G16B16A16_SFLOAT` storage-image feature нужны для environment bake; probe и реальный выбор устройства сообщают одинаковые причины отказа. Surface и surface format должны поддерживать color attachment; surface format также требует blending. HDR scene `R16G16B16A16_SFLOAT` требует color attachment, color-attachment blending, sampling и линейную фильтрацию. LDR post target `R8G8B8A8_SRGB` требует `COLOR_ATTACHMENT`, `SAMPLED_IMAGE` и линейную фильтрацию. `D32_SFLOAT` требует depth attachment, sampled image и линейную фильтрацию для comparison sampler. Текстурные `R8G8B8A8_SRGB` и `R8G8B8A8_UNORM` требуют sampled image, линейную фильтрацию, transfer source/destination и blit source/destination для полной mip-цепочки.
- Проверки расширений instance/device выполняются до их создания; требования платформы и дополнительные расширения из конфигурации дедуплицируются. Отсутствующее расширение приводит к `RenderError::Unsupported`.
- Renderer одинаков для Windows и macOS. На macOS адаптер добавляет portability extensions и флаг instance для MoltenVK; отдельного Metal renderer нет. Loader и surface предоставляются платформой, владение Vulkan-объектами остаётся у renderer.
- Discrete GPU получает приоритет. Общая чистая оценка API, dynamic rendering, synchronization2, device extensions и graphics queue используется и `probe_devices`, и выбором устройства в `Renderer::new`; renderer дополнительно проверяет present queue, surface и форматы. Причины отказа включаются в `NoSuitableDevice`.
- Swapchain использует FIFO и exclusive sharing. Размер ограничивается возможностями surface. При начальном размере 0×0 renderer создаёт instance, устройство, capabilities и общую shadow map, но откладывает swapchain и per-frame offscreen-targets до ненулевого размера.
- Существует два frame slot с отдельными command buffer, fence, acquire semaphore и offscreen-target (цвет и глубина); shadow map и sampler общие, а frame descriptor каждого слота ссылается на них. Проходы используют общую graphics queue. Render-finished semaphore привязан к swapchain image. Acquire ждёт не более 100 мс; `TIMEOUT`/`NOT_READY` пропускают кадр без сигнала acquire semaphore, сброса fence или продвижения frame slot. `OUT_OF_DATE` помечает swapchain для пересоздания. Fence сбрасывается после успешного acquire и записи command buffer, перед submit. Начальный переход output image в color attachment использует source stage `COLOR_ATTACHMENT_OUTPUT` с пустым source access, поэтому acquire wait на этой стадии также упорядочивает переход до записи цвета.
- Render extent вычисляется как `floor(output extent × Frame::view.render_scale)` с минимумом 1×1. Каждому frame slot принадлежат отдельные scene, LDR и output targets, а также cluster/light buffers; viewport имеет такой же набор на каждый слот. Буферы обновляются только после fence владельца и не пересоздаются каждый кадр. CPU инвертирует текущую Vulkan projection без дополнительного camera near/far API, извлекает near/far и строит view-space AABB каждой ячейки; fragment выбирает кластер по `-view_z` и `gl_FragCoord` относительно render extent. Отрицательная высота viewport сохраняет соответствие положительного NDC Y верхнему ряду. Compute записывает для каждого кластера до 128 пересекающихся источников; превышение обрезается в стабильном порядке выбранного списка. Барьер `COMPUTE_SHADER / SHADER_STORAGE_WRITE → FRAGMENT_SHADER / SHADER_STORAGE_READ` публикует записи перед mesh fragments. Нулевое число источников всё равно перезаписывает count каждой ячейки.
- Directional shadows используют отдельный D32 массив из четырёх слоёв 2048×2048; у каждого каскада есть depth view и array sampling view. Local shadows используют отдельный D32 массив `D32_SFLOAT` 1024×1024×32 (128 MiB) с `TYPE_2D_ARRAY` sampling view и 32 depth views. Cube array feature не требуется. Перед каждой scene pass массив целиком переводится в depth attachment, все слои очищаются, а назначенные слои рисуются; неиспользованные остаются depth 1. После записи весь массив переводится в shader-read. Общая graphics queue и barriers упорядочивают чтение и запись между кадрами и viewport-ами; каждый viewport получает собственные матрицы и light metadata в frame-slot buffers. Directional и local passes отдельно cull-ят bounds по light frustum, требуют `casts_shadow` и пропускают blend материалы; mask shader повторно использует base-color alpha и cutoff. `firstInstance` выбирает матрицу слоя в vertex shader. Point PCF выбирает face по доминирующей оси с tie order X, Y, Z; матрица, range depth и face basis совпадают с API `engine-scene`. Spot использует свою perspective-матрицу. Fragment выполняет hardware 3×3 comparison PCF; локальные тени умножают только прямой вклад соответствующего point/spot light. Scene opaque+mask pass очищает HDR `R16G16B16A16_SFLOAT` и depth и сохраняет их. При наличии blend draws отдельный pass загружает оба attachments; depth test остаётся включён, depth write выключен, RGB смешивается по `src_alpha`/`one_minus_src_alpha`. Blend сортируется стабильно от дальнего к ближнему по расстоянию до мирового AABB center. Ambient occlusion умножает только ambient/indirect light; emissive добавляется после direct и ambient. Tonemap pass применяет EV и выбранный оператор один раз и пишет LDR `R8G8B8A8_SRGB`; output pass применяет FXAA либо bilinear sampling и масштабирует изображение до output extent. Для `render_frame` output target — swapchain; для viewport он остаётся доступен UI. Tonemapping выдаёт линейный RGB для аппаратного sRGB encode, alpha содержит perceptual luma для FXAA.
- `create_mesh` вычисляет локальную AABB по всем vertices. `culling.rs` проверяет восемь углов AABB после `DrawCommand::model` против clip planes `w±x`, `w±y`, `z` и `w-z` (depth `[0, 1]`); draw отбрасывается только если все углы вне одного plane. Scene и shadow passes используют собственные camera/light matrices, поэтому off-camera shadow caster сохраняется, если он пересекает frustum света. Отсутствующие bounds и невалидные матрицы оставляют draw видимым; все draw handles валидируются до culling.
- Изменение размера, suboptimal или out-of-date помечают swapchain для пересоздания. Нулевой размер пропускается до acquire. При ошибке после acquire обработчик завершает приложение, после чего renderer очищается.
- Частично созданные Vulkan-ресурсы освобождаются при ошибке инициализации. При `Drop` вызывается `device_wait_idle`; frame descriptor pools уничтожаются до используемых ими shadow resources, обе shadow image и comparison sampler освобождаются до device, а directional/local shadow pipelines — до общего pipeline layout. `Arc` окна остаётся жив до уничтожения surface и instance.
- `device_wait_idle` не доказывает завершение всех операций presentation engine. Maintenance extensions в текущем коде не используются.
- В debug-сборке validation layer включается, только если обнаружен через перечисление instance layers; иначе renderer пишет сообщение в stderr и работает без него. Validation layer в среде выполненных проверок отсутствовал.
- Оверлей рисуется после output filter в том же swapchain color-attachment pass (`LOAD`), поэтому не масштабируется `render_scale`; UI pass также рисует прямо в swapchain. Egui UI использует предумноженную альфу и отдельный sampler `CLAMP_TO_EDGE`. В viewport цвет из sRGB LDR target декодируется при выборке и переводится в гамму для совместимости с egui. Вершины и индексы UI и overlay хранятся в буферах frame slot.
- Каждый viewport получает per-frame HDR scene, tonemap и output targets, свой uniform set для камеры, local shadow matrices и light metadata; обе shadow maps общие и перерисовываются для каждой сцены перед opaque pass. Цели и матрицы меняются после ожидания fence слота, без глобального ожидания устройства. `render_frame` создаёт offscreen targets при первом кадре слота, а не при создании swapchain.
- Отложенное удаление держит mesh, texture и material ресурсы до завершения отправленных кадров; `Drop` очищает очередь после `device_wait_idle`.
- Два timestamp на frame slot измеряют clustering, shadow, scene и tonemap passes; первая отметка ставится перед compute dispatch, output filter и overlay не входят. В editor измеряется первая нарисованная сцена. Query читается после fence слота с учётом `timestampValidBits` и `timestampPeriod`; при нулевом `timestampValidBits` queries не создаются. Начальная отметка не блокирует хвост предыдущего кадра, поэтому время может быть немного занижено.
- Scene pipeline создаётся при инициализации: `TRIANGLE_LIST`, depth test `LESS` с записью, без смешивания и без отсечения граней. Directional shadow pipeline пишет только глубину, использует directional matrices, `LESS`, depth bias `1.25 / 1.75`, `cull NONE` и карту 2048×2048; local shadow pipeline использует те же depth/material rules с local matrix SSBO и картой 1024×1024. Оба используют общий pipeline layout. Viewport и scissor основной сцены динамические и равны render extent, поэтому pipeline не пересоздаются при resize.
- Push constants вершинной стадии занимают 128 байт: матрица модели и матрица нормалей по столбцам. CPU рассчитывает матрицу нормалей без glam; она сохраняет нормали при неравномерном и зеркальном масштабе.
- `FrameUniforms` занимает 640 байт в set 0, binding 0, std140; descriptor виден vertex-, fragment- и compute-стадиям. Смещения: 0 — `view_projection` (mat4), 64 — `inverse_view_projection` (mat4), 128 — четыре directional `shadow_view_projections` (mat4), 384 — `light_direction`, 400 — `light_color`, 416 — `ambient_color`, 432 — `shadow_params`, 448 — `camera_position`, 464 — `environment_rotation` (mat4), 528 — `environment_params`, 544 — `local_light_params` (count в x), 560 — `view` (mat4), 624 — `cluster_params` (near, far, render width/height). Shadow params x — directional shadow flag, y — texel size, z — cascade count; environment params содержат intensity, skybox flag и presence flag. Буфер frame slot перезаписывается после ожидания его fence. Directional image/sampler — set 0, bindings 1–2; local-light SSBO — binding 3; cluster records — binding 4; per-camera cluster AABBs — binding 5; local shadow matrix SSBO — binding 6 (vertex+fragment); local depth array — binding 7 (fragment, comparison sampler binding 2). `GpuLocalLight` — семь `std430 vec4` (112 байт): шесть vec4 со shading/culling данными и `uvec4 shadow_params` со смещением 96, где x — layer base, y — point/spot kind, z — enabled. Матрицы хранятся по 64 байта на слой. Cluster record занимает count и 128 индексов (516 байт); AABB — две vec4 (32 байта). Общие generated constants задают размеры сетки, бюджета слоёв и списков в GLSL и Rust.
- Материал использует set 1: `UNIFORM_BUFFER` binding 0 (32-byte `MaterialUniforms`: `base_color`, затем metallic, roughness, normal_scale и has_normal), `SAMPLED_IMAGE` bindings 1–3 (base color, metallic-roughness, normal) и общий `SAMPLER` binding 4. GPU материал владеет uniform buffer и descriptor pool/set; текстуры хранят image и color space, без descriptor pool. Внутренний default material использует белые sRGB/linear текстуры и flat normal map. Материалы уничтожаются до текстур и общего sampler, затем descriptor layouts.
- Mesh shader перемножает base-color texture, линейный base-color фактор и цвет вершины. Metallic-roughness G/B каналы умножают факторы roughness/metallic. Directional и каждый отобранный point/spot light используют общий Cook-Torrance GGX direct BRDF, height-correlated Smith visibility, Schlick Fresnel, roughness floor 0.045 и diffuse `(1-F) × (1-metallic) × base_color / PI`; результат direct BRDF умножается на PI для сохранения прежней яркости света. Point/spot используют обратный квадрат расстояния с плавным range window; spot cone сравнивает направление луча с нормализованным направлением света, равные углы дают жёсткий край. IBL использует irradiance cubemap для diffuse и prefiltered GGX cubemap вместе с split-sum BRDF LUT для specular; LUT 64×64 RG16F вычисляется CPU один раз при инициализации. Встроенный fallback environment сохраняет ambient-путь для кадров без scene environment, но свёртка и BRDF отличаются от старого `EnvBRDFApprox`, поэтому пиксельная идентичность не гарантируется. Directional и local point/spot lights используют отдельные 3×3 comparison PCF shadow maps; тень локального света умножает только его прямой вклад. HDR scene `R16G16B16A16_SFLOAT` остаётся линейным до tonemap pass, где exposure и выбранный tonemapper применяются один раз, затем output pass выполняет FXAA или bilinear scaling.
- Normal map декодируется из RGB в `[-1, 1]`; `normal_scale` умножает XY. TBN строится из производных мирового положения и UV по согласованным формулам renderer, затем tangent и bitangent отдельно проецируются от нормали и нормализуются. При вырожденных UV/производных используется геометрическая нормаль. База не является MikkTSpace: в `Vertex` нет tangent, viewport/front-face sign flip и специальной фильтрации normal mipmaps нет.
- Все три material texture выборки и производные `dFdx`/`dFdy` выполняются до условий шейдера; отсутствующая normal map выключает её результат флагом `has_normal`. Общий sampler материалов использует линейную фильтрацию texel/mip, `REPEAT`, отключённое сравнение и optional anisotropy до 16. Полная mip-цепочка строится синхронными линейными GPU blit-ами. Shadow arrays используют отдельный linear comparison sampler и `CLAMP_TO_EDGE`.
- Загрузка текстуры синхронная: одноразовый command buffer отправляется в ту же очередь, и renderer ждёт его fence. Вызывать её стоит при загрузке ресурсов, а не каждый кадр.
- Viewport имеет отрицательную высоту, поэтому ось Y clip space направлена вверх. Флаг naga `ADJUST_COORDINATE_SPACE` в `build.rs` выключен, чтобы шейдер сам не переворачивал Y.
- Vertex- и index-буферы каждого меша находятся в `HOST_VISIBLE | HOST_COHERENT` памяти и заполняются один раз при создании; staging-загрузки в device-local память нет. Индексы `u32`. Отдельные mesh/material/texture ресурсы удаляются отложенно; `MeshId` — индекс внутри renderer и id другого renderer с допустимым индексом не распознаётся.
- Поддержан один directional light с четырьмя возможными camera-relative cascades и до 1024 выбранных forward point/spot lights на кадр. Список локальных источников проверяется целиком, консервативно отбрасывается по camera frustum и сортируется по вкладу с исходным индексом как tie-break; лишние видимые источники игнорируются. Среди выбранных источников shadow requests назначаются по camera-distance, с input-index tie-break, в общем бюджете 32 слоя (spot 1, point 6); не помещённые в бюджет lights сохраняют direct lighting без тени. Матрицы point/spot вычисляет `engine-scene`, renderer проверяет индекс, тип и конечность и использует 3×3 comparison PCF; point face выбирается по доминирующей оси. Local D32 array 1024×1024×32 занимает 128 MiB и общая для всех viewport-ов; каждый frame-slot хранит отдельные матрицы и metadata после ожидания своего fence. Для диапазона `< 0.001` runtime не создаёт тень, но сохраняет свет. Spot outer angle 90° остаётся неизменным для освещения, а shadow coverage ограничивается FOV `π − 0.01`. В grid 16×9×24 compute проверяет sphere источника или консервативную сферу spot cone на пересечение view-space AABB; до 128 индексов пишутся в исходном порядке, превышение детерминированно обрезается. Каждый frame slot и viewport-slot владеет отдельными light, cluster-output и bounds SSBO; буферы обновляются после fence владельца, при росте light buffer descriptor меняется до освобождения прежнего буфера, пустой список привязывает валидную dummy-запись и сбрасывает cluster counts. Device probe и выбор устройства проверяют dispatch, storage range, descriptor limits, D32 sampled/linear-comparison usage, array layer count и extent. Дополнительные bump/height карты и vertex tangents не реализованы. Environment bake создаёт radiance cube 512 с mip chain (каждый следующий уровень усредняет 2×2 texel предыдущего), irradiance cube 32 и prefiltered specular cube 128 с шестью mip levels; процедурный источник и Radiance equirectangular panorama используют одинаковый IBL набор. Входы bake и результаты записи ограничиваются конечным диапазоном half `[0, 65504]`; значения выше насыщаются. Environment upload выполняется синхронно при смене источника, а не на каждом кадре. DLSS/FSR не интегрированы; для этого ещё требуются depth/motion vectors, jitter, SDK/FFI и resource usage flags.
- `tessellation_shader` отражает и включает поддерживаемый Vulkan feature, но tessellation shaders и pipeline отсутствуют.
- Scene color и `Frame::clear_color` — линейные HDR RGB; выбранные экспозиция и tonemapper преобразуют их в LDR перед выводом.

## Решения и основания

- Vulkan 1.3, dynamic rendering и synchronization2 — утверждённый минимальный уровень API.
- Render/output resolution разделены, а output pass вынесен отдельно как точка возможного апскейлера. Это не означает наличия готовой DLSS/FSR интеграции.
- GLSL компилируется naga в `build.rs` по выбору пользователя: сборке не нужны Vulkan SDK и `glslc`, ошибки шейдеров видны при `cargo build`. Naga 30 компилирует `std430` runtime-array SSBO mesh shader, compute shaders, `textureCube` и storage images `rgba16f`; fallback для SSBO не требуется.
- Дополнительные расширения задаются в `RendererConfig` до создания instance/device по утверждённому требованию для будущих интеграций.
- `raw-window-handle` позволяет renderer принимать окно без прямой зависимости от winit; `Arc` удерживает окно живым до уничтожения surface. Это подтверждённый контракт владения.
- Оверлей рисуется поверх swapchain после FXAA и upscaling, а не в HDR offscreen-target: при `render_scale < 1` текст иначе размывался бы масштабированием. Renderer принимает только готовые треугольники; шрифт, раскладка и метрики остаются в приложении ([[Engine/Sandbox]]).
- Загрузка GPU для `--debug-overlay` считается по Vulkan timestamps от начала clustered compute до конца tonemap, а не по счётчикам ОС: так выбрал пользователь, чтобы не добавлять платформенный код. Значение отражает только работу этого приложения.

Для кластеризации видимых локальных источников `view` камеры должен быть жёстким аффинным преобразованием (вращение/отражение и перенос, без масштаба или shear). Иначе renderer возвращает `InvalidConfig` до упаковки SSBO. Кадры без видимых локальных источников сохраняют поддержку clip-space проекций, включая треугольник sandbox; при непригодной для Z-кластеров проекции используются пустые bounds.
