# EngineRender

Parent: [[Index]]

## Назначение

`engine-render` создаёт Vulkan instance, surface, устройство и swapchain, записывает глубину сцены в shadow map, рисует меши с текстурой, направленным светом и PCF-тенями в HDR offscreen-target, тонмаппит и масштабирует кадр в окно. Крейту не нужна конкретная оконная библиотека: окно передаёт display/window handles через `raw-window-handle`.

## Зависимости и взаимодействия

- Использует ash 0.38.0 и raw-window-handle 0.6.2; naga 30.0.1 — только build-зависимость. naga 30.0.1 не собирает `glsl-in` без `wgsl-in` или `spv-in`, поэтому в `Cargo.toml` дополнительно включена `wgsl-in`. [[Engine/EnginePlatform]] предоставляет загрузку Vulkan, требования платформы и surface через ash-window 0.13.0.
- Используется в [[Engine/Sandbox]], который передаёт `Arc<Window>` из [[Engine/EngineWindow]], и в [[Engine/RveEditor]] через UI pass. Renderer не зависит от egui: перевод его вывода в примитивы выполняет редактор.
- `engine-render` намеренно не зависит от winit; это проверяется командой `cargo tree -p engine-render`.

## Ограничения и важные детали

- Требуется Vulkan API не ниже 1.3, `dynamicRendering`, `synchronization2`, `VK_KHR_swapchain`, graphics+present queue family, surface с `COLOR_ATTACHMENT` и FIFO, surface-формат с `COLOR_ATTACHMENT` и `COLOR_ATTACHMENT_BLEND`, HDR scene-формат `R16G16B16A16_SFLOAT` с `COLOR_ATTACHMENT`, `SAMPLED_IMAGE` и линейной фильтрацией, LDR post-формат `R8G8B8A8_SRGB` с `COLOR_ATTACHMENT`, `SAMPLED_IMAGE` и линейной фильтрацией, формат `D32_SFLOAT` с `DEPTH_STENCIL_ATTACHMENT` и `SAMPLED_IMAGE` для shadow map, и формат текстур `R8G8B8A8_SRGB` с `SAMPLED_IMAGE`, `SAMPLED_IMAGE_FILTER_LINEAR`, `TRANSFER_SRC`, `TRANSFER_DST`, `BLIT_SRC` и `BLIT_DST`.
- Проверки расширений instance/device выполняются до их создания; требования платформы и дополнительные расширения из конфигурации дедуплицируются. Отсутствующее расширение приводит к `RenderError::Unsupported`.
- Renderer одинаков для Windows и macOS. На macOS адаптер добавляет portability extensions и флаг instance для MoltenVK; отдельного Metal renderer нет. Loader и surface предоставляются платформой, владение Vulkan-объектами остаётся у renderer.
- Discrete GPU получает приоритет. Общая чистая оценка API, dynamic rendering, synchronization2, device extensions и graphics queue используется и `probe_devices`, и выбором устройства в `Renderer::new`; renderer дополнительно проверяет present queue, surface и форматы. Причины отказа включаются в `NoSuitableDevice`.
- Swapchain использует FIFO и exclusive sharing. Размер ограничивается возможностями surface. При начальном размере 0×0 renderer создаёт instance, устройство, capabilities и общую shadow map, но откладывает swapchain и per-frame offscreen-targets до ненулевого размера.
- Существует два frame slot с отдельными command buffer, fence, acquire semaphore и offscreen-target (цвет и глубина); shadow map и sampler общие, а frame descriptor каждого слота ссылается на них. Проходы используют общую graphics queue. Render-finished semaphore привязан к swapchain image. Acquire ждёт не более 100 мс; `TIMEOUT`/`NOT_READY` пропускают кадр без сигнала acquire semaphore, сброса fence или продвижения frame slot. `OUT_OF_DATE` помечает swapchain для пересоздания. Fence сбрасывается после успешного acquire и записи command buffer, перед submit.
- Render extent вычисляется как `floor(output extent × Frame::view.render_scale)` и ограничивается минимумом 1×1. Per-slot targets пересоздаются после ожидания fence своего слота. До scene pass renderer переводит общую shadow map из `UNDEFINED` в depth layout, очищает её до 1.0 и, если `Frame::shadow_view_projection` задана, записывает глубину draw-команд с `casts_shadow`. Затем барьер переводит карту в `SHADER_READ_ONLY_OPTIMAL`; scene pass очищает HDR `R16G16B16A16_SFLOAT` и `D32_SFLOAT`, после чего рисует `DrawCommand`. Tonemap pass применяет EV и выбранный оператор в LDR `R8G8B8A8_SRGB`; output pass выполняет FXAA либо bilinear sampling при масштабировании и пишет в swapchain color attachment, затем переводит изображение в present layout. Тонмаппинг возвращает линейный RGB для аппаратного sRGB encode; alpha хранит luma в perceptual sRGB-пространстве для FXAA. Когда тени выключены, карта всё равно очищается для валидного дескриптора, но draw в shadow pass не записываются.
- Изменение размера, suboptimal или out-of-date помечают swapchain для пересоздания. Нулевой размер пропускается до acquire. При ошибке после acquire обработчик завершает приложение, после чего renderer очищается.
- Частично созданные Vulkan-ресурсы освобождаются при ошибке инициализации. При `Drop` вызывается `device_wait_idle`; descriptor pool уничтожается до используемых им shadow ресурсов, shadow image и sampler освобождаются до device, а shadow pipeline — до общего pipeline layout. `Arc` окна остаётся жив до уничтожения surface и instance.
- `device_wait_idle` не доказывает завершение всех операций presentation engine. Maintenance extensions в текущем коде не используются.
- В debug-сборке validation layer включается, только если обнаружен через перечисление instance layers; иначе renderer пишет сообщение в stderr и работает без него. Validation layer в среде выполненных проверок отсутствовал.
- Оверлей рисуется после output filter в том же swapchain dynamic-rendering pass (`LOAD`), поэтому не масштабируется `render_scale` и остаётся чётким. Для него у swapchain image создаются image views, а pipeline с форматом surface, альфа-смешиванием `SRC_ALPHA / ONE_MINUS_SRC_ALPHA` и без глубины создаётся при инициализации. Вершины лежат в host-visible буфере своего frame slot, перезаписываются после ожидания fence слота и при нехватке места пересоздаются с ёмкостью до следующей степени двойки.
- UI pass: `render_frame_with_ui` не использует blit и рисует прямо в swapchain image, поэтому acquire semaphore ждёт стадию `COLOR_ATTACHMENT_OUTPUT`, а не `TRANSFER`. Pipeline без глубины, с предумноженной альфой `ONE / ONE_MINUS_SRC_ALPHA`, отдельным линейным sampler `CLAMP_TO_EDGE` (`REPEAT` материалов дал бы артефакты на краях атласа) и layout материалов как set 0. Вершины и индексы UI лежат в растущих буферах кадрового слота.
- Цвет UI: шейдер умножает изображение на цвет вершины в гамма-пространстве, как ожидает egui. При sRGB-формате swapchain результат переводится в линейный для корректной записи; viewport хранит финальный LDR sRGB-цвет после tone mapping, sampled image декодируется в линейный, а перед умножением переводится обратно в гамма-пространство с альфой 1. Флаги передаются push constant на каждый примитив.
- Viewport target создаётся отдельно на каждый кадровый слот (HDR scene `R16G16B16A16_SFLOAT`, tonemap LDR `R8G8B8A8_SRGB`, итоговый LDR `R8G8B8A8_SRGB`, глубина, наборы дескрипторов и свой uniform-буфер кадра, потому что у каждой сцены своя камера). Shadow map общая: каждая сцена кадра рисует её заново перед своим проходом. Цель слота используется только его command buffer, поэтому при смене размера или render scale она заменяется после ожидания fence этого слота, без `device_wait_idle`: перетаскивание панели не останавливает GPU. Итоговое изображение между кадрами находится в `SHADER_READ_ONLY_OPTIMAL`.
- Offscreen-цели `render_frame` создаются при первом кадре слота, а не при пересоздании swapchain: редактору они не нужны и заняли бы десятки мегабайт памяти GPU.
- Отложенное удаление: `RetireQueue` держит ресурс, пока fence каждого кадрового слота не дождутся после его добавления. Очередь очищается в `Drop` после `device_wait_idle`. Если кадры не рисуются (свёрнутое окно), ресурсы живут до следующих кадров или уничтожения renderer.
- GPU-время меряют два timestamp на frame slot (query pool сбрасывается в command buffer, `hostQueryReset` не нужен): начало записывается перед shadow pass, конец — после tonemap pass, оба на стадии `COLOR_ATTACHMENT_OUTPUT`. Измерение охватывает shadow, scene и tonemap pass; output filter и overlay не входят. Начальная отметка не блокирует начало shadow pass от хвоста предыдущего кадра, поэтому время иногда немного занижается. Привязка shadow pass к предыдущему кадру сериализовала бы кадры и добавила ожидание vsync. Результат читается без ожидания после fence слота с маской `timestampValidBits` и пересчётом через `timestampPeriod`; при `timestampValidBits == 0` query pool не создаются.
- Scene pipeline создаётся при инициализации: `TRIANGLE_LIST`, depth test `LESS` с записью, без смешивания и без отсечения граней. Отдельный shadow pipeline пишет только глубину, использует только позицию вершины, `LESS`, depth bias `1.25 / 1.75`, `cull NONE` и те же динамические правила viewport/scissor в размере карты 2048×2048. Оба pipeline используют общий pipeline layout. Viewport и scissor основной сцены динамические и равны render extent, поэтому pipeline не пересоздаются при resize.
- Push constants вершинной стадии занимают 128 байт: матрица модели и матрица нормалей по столбцам. CPU рассчитывает матрицу нормалей без glam; она сохраняет нормали при неравномерном и зеркальном масштабе.
- `FrameUniforms` занимает 192 байта в set 0, binding 0, std140; его descriptor виден vertex- и fragment-стадиям. Смещения: 0 — `view_projection` (mat4), 64 — `light_view_projection` (mat4), 128 — `light_direction`, 144 — `light_color`, 160 — `ambient_color`, 176 — `shadow_params` (четыре vec4). У последнего вектора x — флаг теней, y — размер texel `1/2048`. Буфер своего frame slot перезаписывается после ожидания fence этого слота. Свет и shadow image/sampler располагаются в set 0, binding 1 — sampled image и binding 2 — sampler.
- Освещение: `albedo × (ambient + light.color × diffuse × shadow)`, где `diffuse = max(dot(n, -direction), 0)`, а `albedo` — текстура, умноженная на цвет вершины. Одна общая D32 shadow map 2048×2048; PCF вручную сравнивает глубину в окне 3×3 с bias `max(0.005 × (1 − dot(n, l)), 0.0005)`. Фрагмент за пределами shadow clip volume считается освещённым. Тени отключаются через `Frame::shadow_view_projection = None`. Specular и каскады не реализованы. Параметры света и обе матрицы лежат в per-frame uniform buffer.
- Текстура материала — set 1: `SAMPLED_IMAGE` (binding 0) и `SAMPLER` (binding 1), потому что GLSL-фронтенд naga работает с раздельными `texture2D` и `sampler`. Один общий sampler материалов использует линейную фильтрацию по текселям и mip-уровням, `REPEAT` и отключённое сравнение. Полная цепочка mip-уровней строится один раз при синхронной загрузке через линейные GPU blit-ы; image view охватывает всю цепочку. Если устройство поддерживает `samplerAnisotropy`, sampler включает его с пределом `min(16, maxSamplerAnisotropy)`; иначе анизотропия выключена. У каждой текстуры свой descriptor pool на один набор. Белая текстура 1×1 создаётся при инициализации под внутренним индексом 0. Shadow map использует отдельный sampler с NEAREST и `CLAMP_TO_EDGE`.
- Загрузка текстуры синхронная: одноразовый command buffer отправляется в ту же очередь, и renderer ждёт его fence. Вызывать её стоит при загрузке ресурсов, а не каждый кадр.
- Viewport имеет отрицательную высоту, поэтому ось Y clip space направлена вверх. Флаг naga `ADJUST_COORDINATE_SPACE` в `build.rs` выключен, чтобы шейдер сам не переворачивал Y.
- Vertex- и index-буферы каждого меша находятся в `HOST_VISIBLE | HOST_COHERENT` памяти и заполняются один раз при создании; staging-загрузки в device-local память нет. Индексы `u32`. Буферы освобождаются отложенным `destroy_mesh` или в `Drop` после `device_wait_idle`. `MeshId` — индекс внутри renderer; id другого renderer с допустимым индексом не распознаётся.
- UI-текстуры имеют один mip-уровень: `update_ui_texture` обновляет только mip 0, а цепочка для них не нужна.
- Нормальных карт, PBR-материалов, нескольких источников света, specular, каскадных и других дополнительных карт теней нет. Между render resolution и output resolution уже есть offscreen-target и отдельная output-функция, но DLSS/FSR не интегрированы. Для такой интеграции ещё отсутствуют, в частности, depth/motion vectors, jitter, SDK/FFI и необходимые ресурсные usage flags.
- `tessellation_shader` отражает и включает поддерживаемый Vulkan feature, но tessellation shaders и pipeline отсутствуют.
- Scene color и `Frame::clear_color` — линейные HDR RGB; выбранные экспозиция и tonemapper преобразуют их в LDR перед выводом.

## Решения и основания

- Vulkan 1.3, dynamic rendering и synchronization2 — утверждённый минимальный уровень API.
- Render/output resolution разделены, а output pass вынесен отдельно как точка возможного апскейлера. Это не означает наличия готовой DLSS/FSR интеграции.
- GLSL компилируется naga в `build.rs` по выбору пользователя: сборке не нужны Vulkan SDK и `glslc`, ошибки шейдеров видны при `cargo build`.
- Дополнительные расширения задаются в `RendererConfig` до создания instance/device по утверждённому требованию для будущих интеграций.
- `raw-window-handle` позволяет renderer принимать окно без прямой зависимости от winit; `Arc` удерживает окно живым до уничтожения surface. Это подтверждённый контракт владения.
- Оверлей рисуется поверх swapchain после FXAA и upscaling, а не в HDR offscreen-target: при `render_scale < 1` текст иначе размывался бы масштабированием. Renderer принимает только готовые треугольники; шрифт, раскладка и метрики остаются в приложении ([[Engine/Sandbox]]).
- Загрузка GPU для `--debug-overlay` считается по Vulkan timestamps shadow и scene pass, а не по счётчикам ОС: так выбрал пользователь, чтобы не добавлять платформенный код. Значение отражает только работу этого приложения.
