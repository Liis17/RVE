# Engine Audio

`engine/engine-audio` воспроизводит клипы `.wav` и `.ogg` из ресурсов проекта. Крейт не зависит от renderer и script runtime: микшер, декодеры и мост к сцене тестируются без устройства, а вывод на устройство по умолчанию идёт через `cpal`. Зависимости: `engine-scene` (типы компонента и запросов), `engine-resources` (чтение байт), `cpal`, `lewton`, `flume`, `log`. Потребители: `engine-runtime` и `rve-editor`.

## Контракты

- `AudioEngine::new(AudioConfig { resources, output }) -> (AudioEngine, AudioHandle)`; `run(self)` блокирует поток до `AudioHandle::shutdown()` или до освобождения всех хендлов. `resources` задают чтение клипов, `output` открывает устройство. Без устройства (или при ошибке его открытия) звук молча выключается, пишется `warn!`, работа продолжается.
- `AudioHandle` клонируется. `play(voice, path, PlayRequest)`, `stop`, `stop_all`, `set_paused`, `set_voice_volume`, `set_group_volume`, `preload`, `set_emitter`, `set_listener`, `poll_events`, `shutdown`. Голоса адресуются `VoiceId` из `engine-scene`; id выделяет `VoiceId::allocate()` один раз за процесс и не повторяет.
- `AudioBridge` связывает `World` с хендлом: `start(&World)` запоминает `[[assets]]`, предзагружает клипы источников и запускает `play_on_start`; `apply(requests, &World)` применяет `AudioRequest` скриптов; `sync_positions(&World)` пишет позицию излучателя каждого пространственного источника и позицию слушателя (активная камера). Исчезнувший объект останавливает свой голос. `emitter_of(object)` возвращает последнюю переданную позицию.
- `AudioEvent::VoiceEnded(VoiceId)` приходит, когда голос закончился, был остановлен или вытеснен. Мост по нему убирает источник из таблицы «объект → голос», поэтому one-shot можно запустить снова.
- Клип `[[assets]]` сцены объявляется в документе; путь вне набора проигрывается, но `warn!` предупреждает, что release его не упакует.

## Потоки и real-time

- `rve-audio` (`AudioEngine::run`) владеет кешем клипов, очередью ожидающих запусков и `cpal::Stream`; `Stream` создаётся и живёт в этом потоке. Команды приходят из `AudioHandle` через ограниченную очередь на 1024; при переполнении `play`/`stop` возвращают `AudioError::QueueFull`.
- `rve-audio-decode` декодирует прочитанные байты, чтобы цикл команд не блокировался. Чтение идёт через неблокирующий `ResourceRequest::try_receive`.
- Callback выходного потока не выделяет память, не берёт `Mutex` и не освобождает клипы: голос держит `Arc<Clip>`, а кеш потока держит ту же ссылку. Команды в callback передаются очередью на 1024 и вычитываются пачками по 256; завершённые голоса возвращаются через `try_send` и накапливаются в фиксированном буфере, если очередь полна.
- Позиции излучателей и слушателя не идут через очередь. Они лежат в seqlock-таблице по полосе на голос (64 полосы) и одной полосе слушателя: писатель один, новое значение перезаписывает старое, переполнения нет.

## Микшер

- Пул из 64 голосов с полосами; полоса голоса совпадает со слотом микшера. При полном пуле `AudioHandle::play` вытесняет самый старый не-looping голос; если все заняты зацикленными, возвращается `AudioError::NoFreeVoice`.
- Ресемплинг линейный (clip rate → device rate). Голос читает `f64`-позицию; зацикленный голос перескакивает к началу без паузы.
- Затухание: `d ≤ min` → 1; `d ≥ max` → 0; между ними `(min/d)·(max−d)/(max−min)`. Панорама — constant-power по `dot(направление, правая ось слушателя)`; излучатель в точке слушателя звучит по центру.
- Громкость голоса = `master · группа · volume · затухание`, меняется линейно внутри блока 256 кадров; остановка — fade-out около 5 мс.
- Группы фиксированные: `Master`, `Music`, `Effects`, `Ambient`. Сцена задаёт `music|effects|ambient`, `master` допустим только для `set_group_volume`.
- Вывод: моно получает `(L+R)/2`, стерео — `L`/`R`, каналы сверх двух — нули. Клипы моно и стерео; клипы с другим числом каналов отклоняются.
- Форматы устройства: `f32`, `i16`, `u16`, `i32`. Остальные — ошибка открытия, звук выключается.

## Декодирование

- WAV: свой разбор RIFF. PCM 8/16/24/32 бит и float32, включая `WAVE_FORMAT_EXTENSIBLE`; неизвестные chunk пропускаются. Заявленный размер `data` больше файла — ошибка до аллокации.
- Ogg Vorbis: `lewton`, пакеты добавляются по одному с проверкой лимита.
- Лимиты: клип не длиннее 64·2^20 сэмплов f32 (256 МБ); суммарный кеш декодированных клипов не больше 512 МБ. Превышение — ошибка загрузки и `warn!`, без паники.
- Стриминга нет: трёхминутный стерео-трек 48 kHz занимает около 55 МБ в памяти. Это ограничение текущей версии.

## Поведение при ошибках

- Ошибка чтения или декодирования клипа: `warn!` один раз для пути, путь помечается ошибочным, его ожидающие запуски снимаются с мест (слот освобождается, звука нет). Повторный запуск того же пути сразу отказывает без нового чтения.
- Остановка до завершения загрузки отменяет ожидающий запуск: голос не появится.
- Пауза (`set_paused`) замораживает микшер: тишина, позиции не двигаются.

## Скрипты и запросы

Скрипты не вызывают поток напрямую. Запросы копятся в транзакции скрипта и попадают в `ScriptHost::drain_audio_requests()` только после успешного commit; при ошибке скрипта они отбрасываются вместе с остальными записями. Lua API и SDK описаны в [[Engine/EngineScript]] и [[Engine/RveSdk]].

## Интеграция

- Runtime (`engine-runtime`): `start_modules` создаёт движок с ресурсами проекта и `output: true`, поток `rve-audio` останавливается через `shutdown`. Scripts thread после `start` вызывает `bridge.start`, после `update` — `apply`, после `build_frame` — `sync_positions`. В background-режиме звук играет, позиции не обновляются.
- Редактор (`rve-editor`): `PlaySession` создаёт собственный движок при Play и останавливает его при Stop и Drop. `sync_positions` вызывается в `step` после пересчёта мировых матриц, потому что редактор не вызывает `build_frame`. Пауза Play отправляет `set_paused`.

## Ограничения

- Macos (CoreAudio) не проверялась на рабочей машине: сборка и тесты идут через CI.
- Редактор не устанавливает backend для `log`, поэтому предупреждения об устройстве видны только в runtime.
- Вытеснение голоса обрывает старый звук без fade-out.
- Стриминга и эффектов нет, эквалайзера и ревербераций нет.

## Решения

- Собственный микшер на `cpal`, без внешнего движка. Решение пользователя. Цена: поддерживаем ресемплинг и затухание сами.
- Звук не блокирует цикл: декодирование и чтение вне потока команд, позиции через seqlock. Цена: сложность по сравнению с простой очередью.
- `VoiceId` выделяется в процессе, а не потоком аудио, поэтому скрипт получает id сразу, до применения запроса.
